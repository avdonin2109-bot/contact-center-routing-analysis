# Contact Center Routing Analysis

Аналитический проект по исследованию маршрутизации звонков в контактном центре.

Проект показывает полный цикл подготовки аналитического решения: от генерации синтетических данных о звонках до SQL-обработки, подготовки данных в Excel и построения дашборда в Yandex DataLens.

> **Важно:** проект полностью работает на синтетических данных. Реальные данные, идентификаторы, номера телефонов, логины сотрудников и внутренние параметры компании не используются.

---

## О проекте

В контактном центре один клиентский звонок может проходить через несколько последовательных сегментов: входную точку, очередь, IVR, робота, оператора, консультацию или повторную передачу другому оператору.

Из-за этого один звонок может содержать несколько последовательных взаимодействий с контактным центром.

Цель проекта:

* восстановить последовательность сегментов звонка;
* определить цепочки маршрутизации;
* определить количество переводов;
* рассчитать время ожидания и разговора;
* учитывать hold и консультации;
* выделить время, проведенное между сегментами;
* подготовить агрегированные показатели для анализа;
* представить результат в виде BI-дашборда.

Проект является синтетической воспроизведенной версией аналитического процесса, который применяется для анализа контакт-центра.

---

## Бизнес-задача

Необходимо понять, как звонки проходят через контактный центр и какие характеристики имеют маршруты с несколькими сегментами.

Основные вопросы анализа:

1. Сколько звонков проходит через несколько сегментов?
2. Сколько переводов приходится на звонок?
3. Какие навыки чаще встречаются в начале маршрута?
4. Сколько времени клиент проводит в ожидании?
5. Сколько времени занимает разговор?
6. Какую долю времени занимают hold и консультации?
7. Какие цепочки маршрутизации встречаются чаще всего?
8. Как распределяются звонки по количеству сегментов?
9. Какие характеристики маршрутизации можно использовать для дальнейшего анализа процессов контактного центра?

## Данные

Данные полностью синтетические и генерируются программно.

Одна запись соответствует одному сегменту звонка.

Основные сущности:

* звонок;
* сегмент звонка;
* оператор;
* skill;
* входная точка;
* время ожидания;
* время разговора;
* hold;
* консультация;
* результат обработки;
* номер клиента;
* идентификатор звонка.

### Основные поля

| Поле              | Описание                              |
| ----------------- | ------------------------------------- |
| `call_id`         | Идентификатор синтетического звонка   |
| `call_date`       | Дата звонка                           |
| `event_at`        | Дата и время сегмента                 |
| `segment_no`      | Порядковый номер сегмента             |
| `agent_login`     | Синтетический идентификатор оператора |
| `exit_skill`      | Skill сегмента                        |
| `total_wait_sec`  | Общее синтетическое время ожидания    |
| `talk_sec`        | Время разговора                       |
| `hold_sec`        | Время hold                            |
| `consult_sec`     | Время консультации                    |
| `caller_number`   | Синтетический номер клиента           |
| `dialed_number`   | Синтетическая входная точка           |
| `global_call_uid` | Синтетический идентификатор звонка    |
| `crm_payload`     | Синтетические дополнительные данные   |

## Генерация данных

Для создания воспроизводимого набора используется Python-генератор.

Генератор моделирует звонки с различным количеством сегментов.

Количество сегментов:

```text
1–8 сегментов на звонок
```

Используются различные типы сегментов:

* entry;
* queue;
* agent;
* consult;
* robot;
* IVR;
* feedback;
* internal.

Также используются заранее заданные типовые цепочки маршрутизации.

Генератор использует фиксированный random seed, поэтому один и тот же набор параметров позволяет воспроизводить результаты.

Файл генератора:

```text
src/synthetic_call_generator.py
```

## SQL-анализ

После генерации данные загружаются в SQLite и анализируются через SQL.

Для работы с базой используется DBeaver.

Основные этапы SQL-обработки:

### 1. Подготовка исходных данных

* фильтрация периода;
* сортировка сегментов внутри звонка;
* формирование порядкового номера сегмента.

### 2. Определение сегментов операторов

Выделяются сегменты, содержащие оператора и skill.

### 3. Построение цепочки

Для каждого звонка восстанавливается последовательность сегментов.

Например:

```text
Entry
  ↓
Queue
  ↓
Agent / Skill 121
  ↓
Feedback
  ↓
Agent / Skill 137
```

### 4. Расчет переводов

Количество переводов определяется по количеству последовательных операторских сегментов.

### 5. Расчет времени

Для каждого звонка рассчитываются:

* ожидание;
* разговор;
* hold;
* консультация;
* время между сегментами.

### 6. Формирование итогового набора

Результат SQL-обработки переводится на уровень одного звонка.

Пример структуры:

```text
CallID
Дата
Номер клиента
Skill1
Skill2
Skill3
...
Ожидание Skill1
Разговор Skill1
Hold Skill1
Консультация Skill1
...
Количество переводов
Время мостов
Ожидание до последнего сегмента
Разговор до последнего сегмента
```

## Excel

После SQL-обработки результат проходит дополнительную подготовку в Excel.

Используются:

* формулы;
* структурированные таблицы;
* сводные таблицы;
* при необходимости Power Query.

Цель Excel-этапа:

* проверить результат SQL;
* подготовить поля для BI;
* привести структуру данных к удобному виду;
* выполнить дополнительные преобразования, необходимые для визуализации.

Excel в данном проекте является промежуточным аналитическим слоем между SQL и BI.

## Yandex DataLens

Подготовленный набор данных загружается в Yandex DataLens.

На его основе строится дашборд для анализа маршрутизации звонков.

Планируемые блоки дашборда:

### KPI

* количество звонков;
* количество звонков с несколькими сегментами;
* количество переводов;
* среднее количество переводов на звонок;
* среднее время ожидания;
* среднее время разговора.

### Анализ маршрутизации

* распределение звонков по количеству сегментов;
* наиболее частые начальные skills;
* наиболее частые цепочки;
* распределение переводов;
* время ожидания по маршрутам.

### Детализация

Таблица с возможностью анализировать отдельные цепочки и характеристики звонков.

## Ограничения

Проект не является копией производственной базы данных.

Синтетическая модель упрощает некоторые элементы реального контакт-центра:

* структура сегментов;
* VDN;
* идентификаторы звонков;
* данные клиентов;
* операторы;
* временные характеристики;
* маршрутизация.

Поэтому результаты проекта предназначены для демонстрации аналитического подхода и технического процесса, а не для оценки реальной работы контактного центра.
