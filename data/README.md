# Data

В этой директории находятся данные, используемые в проекте для SQL-анализа маршрутизации звонков.

## Источник данных

Все данные в проекте являются **полностью синтетическими** и генерируются программно с помощью Python.

Реальные данные контактного центра в репозитории не используются.

Генератор находится в:

```text
../src/synthetic_call_generator.py
```

## Структура данных

Основной набор данных содержит записи на уровне сегмента звонка.

Один звонок может состоять из нескольких сегментов.

Пример:

```text
Call 100001
│
├── Segment 1 → Entry
├── Segment 2 → Queue
├── Segment 3 → Agent / Skill 121
├── Segment 4 → Feedback
└── Segment 5 → Agent / Skill 137
```

Каждая строка исходного набора соответствует одному сегменту.

Основные поля:

| Поле              | Описание                              |
| ----------------- | ------------------------------------- |
| `call_id`         | Синтетический идентификатор звонка    |
| `call_date`       | Дата звонка                           |
| `event_at`        | Дата и время сегмента                 |
| `segment_no`      | Порядковый номер сегмента             |
| `agent_login`     | Синтетический идентификатор оператора |
| `exit_skill`      | Skill сегмента                        |
| `total_wait_sec`  | Синтетическое время ожидания          |
| `talk_sec`        | Время разговора                       |
| `hold_sec`        | Время удержания                       |
| `consult_sec`     | Время консультации                    |
| `caller_number`   | Синтетический номер клиента           |
| `dialed_number`   | Синтетическая входная точка           |
| `global_call_uid` | Синтетический идентификатор звонка    |
| `crm_payload`     | Синтетические дополнительные данные   |

## Генерация

Данные создаются скриптом:

```text
../src/synthetic_call_generator.py
```

Генератор позволяет воспроизводимо создавать набор данных с заданными параметрами:

* количеством звонков;
* периодом;
* количеством сегментов;
* распределением типов сегментов;
* количеством операторов;
* набором skills;
* временными характеристиками.

Для воспроизводимости используется фиксированный `random seed`.

## Использование

После генерации данные загружаются в SQLite и используются для SQL-анализа.

Далее результат SQL-обработки передается на этап Excel-предобработки и последующей визуализации в Yandex DataLens.

## Конфиденциальность

Данные не содержат:

* реальных номеров телефонов;
* реальных CallID;
* реальных UCID;
* реальных логинов сотрудников;
* реальных клиентских данных;
* внутренних идентификаторов компании.

Набор предназначен исключительно для демонстрации аналитического процесса.
